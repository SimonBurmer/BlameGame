## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
iOS launches into a pure-white screen holding a 1x1 transparent LaunchImage.png — the untouched Flutter default. The app itself is dark navy, so every cold start flashes white and then snaps to dark, which reads as a broken app before a tester has tapped anything.

The launch screen cannot run Dart, so it has to be a storyboard: the brand background colour plus the logo mark as a real launch image at 1x/2x/3x. Android's LaunchTheme has the same gap.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The iOS launch screen is the brand background with the logo mark, at 1x/2x/3x, with no white flash
- [x] #2 Android's launch theme matches rather than showing the default white
- [x] #3 The launch images are generated by scripts/generate-app-icons.sh from the branding SVGs, not hand-placed
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
iOS storyboard ground is AppColors.dark.bgTop (#1A1A2E) with the logo mark at 120pt (1x/2x/3x); Android gets the same colour plus @mipmap/launch_image, and NormalTheme's windowBackground moved off ?android:colorBackground so nothing white shows behind the Flutter view either. All launch images come out of scripts/generate-app-icons.sh.

Verified by holding the app at launch with 'xcrun simctl launch --wait-for-debugger', which keeps the launch screen up long enough to screenshot — a plain launch renders it for well under one screenshot interval.
<!-- SECTION:NOTES:END -->
